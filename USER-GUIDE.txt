CONTRACT BUILDER
USER INSTRUCTIONS

FIRST RUN

This application is not code-signed. The first time you open a downloaded
copy, Windows SmartScreen or macOS Gatekeeper may show a security warning
or block the app. This is expected. Only continue if you obtained the app
from this project's official GitHub release.

Windows

1. When Windows SmartScreen says "Windows protected your PC", select More
   info.
2. Check that the app is Contract Builder, then select Run anyway.

macOS

1. In Finder, locate Contract Builder.app. Control-click (or right-click)
   it and choose Open.
2. When macOS asks you to confirm, choose Open.

You should need to approve the app only the first time on each computer.

On Windows, an update installed by the application itself should not trigger
the SmartScreen warning again. The app downloads the update directly, rather
than through a browser, so the file should not receive the internet-download
mark that triggers the warning. This behavior has not yet been confirmed on a
real Windows PC; see T-002 in TASKS.md.

WHAT THIS DOES

Contract Builder reads a Word document containing placeholders, asks you
to fill in those placeholders, and saves a completed copy as a new .docx file.
The original template is never changed.

1. CHOOSE WHERE TO START

At the top, under "Build contract from:", pick one of three buttons (or press
Alt and the underlined letter):

  Existing contract assembly - open one you saved before.
  New contract assembly      - choose components and build a new one.
  Word file                  - select a Word .docx or .dotx file.

For a Word file:

The application scans the document and finds each unique placeholder. A
placeholder is a field name enclosed in double curly braces, for example:

    {{Recipient Name}}

2. FILL IN THE FIELDS

The application creates one input for each unique field, in the order the
fields first appear in the document.

Type the information requested. If the same placeholder appears several
times, you only need to fill it in once; every occurrence will receive the
same value.

A placeholder can appear in the main text, tables, headers, footers,
footnotes, or endnotes. The application fills in all of these locations.

Some templates may use specialized fields, such as dates, amounts, lists, or
choices. The application applies the formatting specified by the template.
For ordinary text fields, your entry is inserted as you type it.

PUBLISHER PROFILES

The application can save reusable international-publisher information locally.

1. Choose Publishers > Manage publisher profiles.
2. Select New profile and enter the publisher name and any available contact,
   website, and mailing-address information.
3. Click Save profile. You can return later to edit or delete the record.
4. Choose a Word template, select the publisher in the Saved publisher list,
   and click Load into fields.

The application fills only template fields it recognizes. The initial field
mapping includes common labels such as:

    {{International Publisher Name}}
    {{Publisher Name}}
    {{International Publisher Contact}}
    {{Contact Person}}
    {{International Publisher Contact Title}}
    {{International Publisher Email}}
    {{International Publisher Phone}}
    {{International Publisher Website}}
    {{International Publisher Address}}
    {{International Publisher Country}}

Address components are assembled into a multiline postal address when the
template uses a general publisher-address field. A template field that does
not match a known publisher field is left alone for you to complete.

If loading a profile would replace information already entered, the application
asks before making the change. Loading a profile does not modify the saved
profile. Changes made in the contract form apply only to that contract.

Extra details, such as Publisher type

In the Publisher Profiles window, "More about this publisher" holds extra
details you define yourself. Click "Add a detail…", name it (for example
Publisher type) and list its choices, one per line (Non-profit, Sole
proprietor, Company). Each profile then has a drop-down for it, so the saved
value always matches what your wording tests for. A field with the same name
as the detail, such as {{Publisher Type}} in {{#if Publisher Type = Non-profit}},
is filled when you choose the publisher, and the right alternative wording is
used without anyone answering a question. If a publisher has no value saved,
the field is left for you to choose and the message says so.

More than one publisher in a contract

If one contract names two publishers, choose Publishers > Parties in a
contract and add a party for each, such as Publisher One (role: Proprietor)
and Publisher Two. Fields that start with the party's name are then filled
from the publisher you choose for that party: "Publisher One's Address",
"Publisher One's State", "Publisher Two's Contact" and so on, with or without
the apostrophe. A field named exactly for the party, or for the party and its
role in brackets, such as "Publisher One (Proprietor)", is filled with the
publisher's name. The form shows one publisher choice for each party that
appears in the document, each with its own "Fill all" button, and every field
it can fill has a "From publisher" button. Changes to the parties apply the next
time you open the template or assembly. A document with one publisher works as
before.

Help under each field

If a field has a description (set in the field's edit window), it appears in
small grey text under the field in the form. It is guidance for the person
filling in the form and is never put in the document.

Publisher profiles are stored in a local SQLite database in your user data
directory. On Windows, this is normally under
%LOCALAPPDATA%\Contract Builder. On macOS, it is under
~/Library/Application Support/Contract Builder. On Linux, it is under
$XDG_DATA_HOME/Contract Builder or ~/.local/share/Contract Builder.
If you used an earlier version called Word Template Filler or TMAI Contract
Builder, rename its folder ("TMAI Contract Builder" or "Word Template Filler")
to "Contract Builder" in the same place before you open this version, so that
your publisher profiles, saved shell and update settings are found.
Back up publisher_profiles.sqlite3 if you need to move your saved profiles to
another computer or preserve them during a system migration.

3. CREATE THE DOCUMENT

Click Create document and choose where to save the completed file.

The application checks formatted entries before creating the document. If a
field is empty, it tells you and asks whether to continue. Empty fields are
represented by an underline (__________) so they can be completed later in Word.

The completed document is saved separately. The template remains unchanged.

HIGHLIGHTING

Select Highlight inserted text for review to mark the wording inserted by the
application in yellow. This can help you review the completed document. It
does not change the template.

WRITING A TEMPLATE

A template is an ordinary Word document (.docx or .dotx). Type the wording
that never changes. Put the name of each changing part inside double braces:

    This Agreement is made between TMAI and {{Client Name}}.

Use the same field name wherever the same information appears. The
application asks for it once. Capitalization and extra spaces in a field
name do not matter. In Word, format the placeholder as you want the inserted
wording to look; the inserted text takes the formatting of the placeholder.

FORMATS

To format an entry, put a vertical bar (|) after its name, followed by the
format. You can use different formats for the same field in different places.

Dates (type a date such as 10/5/2026 or October 5, 2026):

    {{Start Date | date}}          October 5, 2026
    {{Start Date | date-formal}}   5th day of October, 2026
    {{Start Date | date-short}}    10/05/2026

Amounts (type a number such as 12500 or 12,500.50):

    {{Fee | money}}                $12,500.50
    {{Fee | money-words}}          Twelve Thousand Five Hundred
                                   Dollars and Fifty Cents ($12,500.50)
    {{Fee | money-whole}}          $12,501 (rounded to whole dollars)

Numbers:

    {{Notice Days | number}}       30 becomes 30
    {{Notice Days | number-words}} 30 becomes thirty (30)

Other formats:

    {{Client Name | upper}}        ACME CORPORATION
    {{Scope | long}}               Allows several lines of text
    {{Titles | list}}              Type one title per line; two become
                                   "Title A and Title B"; three become
                                   "Title A, Title B, and Title C"
    {{Titles | plural: work, works}}
                                   Says "work" for one title and "works"
                                   for more than one
    {{State | choice: Texas, Oklahoma, Louisiana}}
                                   Shows a drop-down list of those choices

For a list, type one item on each line in the form. A plural field counts
the lines in a list, or a number if you enter one. The two words after
plural: are the singular and plural forms, in that order. Use a slash
instead of a comma if either wording itself contains a comma:

    {{Titles | plural: it, as written / them, as written}}

CHOOSING THE RIGHT KIND OF FIELD

Choose a field by asking what information the person filling in the contract
needs to provide.

- **Plain text**: use this for a name, address, description, or other wording
  that should appear just as it is entered.
  
      {{Client Name}}
      {{Mailing Address | long}}

- **Date**: use this when the person should enter a date. Choose the format
  that matches how it should appear in the contract.
  
      {{Signing Date | date}}
      {{Signing Date | date-formal}}

- **Amount**: use this for money. The person enters the amount once; choose
  the format for how it should appear.
  
      {{One-time Fee | money}}
      {{One-time Fee | money-words}}

- **List**: use this when the person may enter several items, one per line.
  The application joins the items into a readable list.
  
      {{Covered Services | list}}

- **Choice**: use this when the person should select one of several complete
  wordings. Put the alternatives after `choice:`, separated by commas. If an
  alternative itself contains a comma, separate the alternatives with a slash.
  
      {{One-time Fee Wording | choice: The one-time fee is due with the first installment / No one-time fee is charged}}

  The form shows a drop-down list. The selected wording is inserted where the
  field appears.

- **Yes/no clause**: use this when a whole phrase or clause should appear only
  when something is true. Put the wording between `{{#if Field Name}}` and
  `{{/if}}`. The form shows a check box when the field is used only this way.
  
      {{#if One-time Fee Applies}}
      The one-time fee is due with the first installment.
      {{else}}
      No one-time fee is charged.
      {{/if}}

  The checked wording appears when the box is checked; the `{{else}}` wording
  appears when it is not. You can also leave out `{{else}}` if nothing should
  appear when the box is unchecked.

- **Different wording by a value**: use this when the wording depends on
  which value the person selects. Write a condition with `=` and the value
  to test.
  
      {{#if Payment Method = Check}}
      Make the payment by check.
      {{else}}
      Make the payment by electronic transfer.
      {{/if}}

  The form shows a drop-down list containing the values in the conditions.

- **Singular or plural**: use this when a word changes according to the number
  of items. Put the singular and plural forms after `plural:`.
  
      {{Covered Services | plural: service, services}}

  The person enters a number or a list, and the application chooses the
  matching word.

| If the person filling in the form needs to… | Use… |
| --- | --- |
| Enter wording that will appear as written | Plain text |
| Enter a date | Date |
| Enter an amount of money | Amount |
| Enter several items, one per line | List |
| Pick one of several complete phrases | Choice |
| Say whether a clause applies | Yes/no clause |
| Choose a value that changes the wording | Different wording by a value |
| Use a word that changes with the number of items | Singular or plural |

Keep field names short and describe what the person should enter. For
example, use `{{Signing Deadline}}`, not a whole sentence such as
`{{What date must the agreement be signed by?}}`. The field name becomes
the label beside the box in the form.

A worked example
----------------

Suppose a contract needs to say whether a one-time fee is charged. You can
write the alternatives as one **Choice** field:

    {{One-time Fee Wording | choice: The one-time fee is due with the first installment / No one-time fee is charged}}

The form shows a drop-down with these two choices:

  - The one-time fee is due with the first installment
  - No one-time fee is charged

The selected sentence appears in the contract.

Or use a **Yes/no clause** if you want a check box instead:

    {{#if One-time Fee Applies}}
    The one-time fee is due with the first installment.
    {{else}}
    No one-time fee is charged.
    {{/if}}

The form shows a check box labelled **One-time Fee Applies**. When it is
checked, the contract says, "The one-time fee is due with the first
installment." When it is not checked, the contract says, "No one-time fee is
charged."

Both approaches can produce the same wording. Use Choice when the person
should select a complete wording from a list; use a Yes/no clause when a
simple check box is clearer.

OPTIONAL AND ALTERNATIVE WORDING

To include a whole paragraph or group of paragraphs only when a box is
checked, put {{#if Field Name}} and {{/if}} on separate lines around it:

    {{#if Include Non-Compete}}
    The parties agree not to compete during the term of this Agreement.
    {{/if}}

A field used only this way appears as a check box. The wording inside the
braces is included when the box is checked and omitted when it is not.

To show one wording or another based on a choice, put {{else}} between
the alternatives:

    {{#if Governing State = Texas}}
    Texas law governs this Agreement.
    {{else}}
    The law of the selected state governs this Agreement.
    {{/if}}

The comparison creates a drop-down list containing the values used in the
conditions. You can also test whether a value is different:

    {{#if Governing State != Texas}}
    This Agreement is not governed by Texas law.
    {{/if}}

A field by itself is true when it has a value. Add "not" to test when it is
blank or unchecked:

    {{#if Guarantor Name}}
    {{Guarantor Name}} guarantees the obligations.
    {{/if}}

    {{#if not Guarantor Name}}
    No guarantor is named.
    {{/if}}

You can also put a short optional phrase inside a sentence:

    Payment is due in 30 days{{#if Late Fee}}, with a late fee of
    {{Late Fee | money}}{{/if}}.

Word's automatic clause numbering adjusts when an optional paragraph is
removed. Keep the opening and closing markers on their own lines for
whole-paragraph clauses; the short phrase form can stay within a paragraph.

TEMPLATE CHECKS

The application detects common placeholder mistakes, including missing
braces and invalid template syntax. Correct reported problems in Word and
select the template again.

A note about tracked changes, comments, highlighting, or other unusual Word
formatting does not necessarily mean the template is invalid. Review such
notes before relying on the completed document.

STARTING A CONTRACT

The first screen has a "Build contract from" row with three choices:

- **Existing contract assembly**: open a contract you saved before. The list
  shows the saved assemblies; choose one and press Open. The fields appear
  straight away, filled in with the wording of the latest saved version.
- **New contract assembly**: choose the components and build a new contract.
- **Word file**: fill in a Word document that has {{fields}}.

Under the three choices is a short **Recent** list of the Word files and
assemblies you used most recently. Press an item's button to open it again in
one click. If a file has been moved or deleted, its line says "file not found";
choose the file again, or press **Remove from list** to take it off the list.
The list is kept on this computer only.

COMPONENTS AND ASSEMBLED CONTRACTS

A component is a piece of reusable contract wording, such as a payment clause.
You can build a contract from components instead of starting from a Word
template. The Word-template workflow above is unchanged; use whichever suits
the job.

Writing a component

1. Choose Components > Manage components, then New component.
2. Give it a name (a category and tags are optional, and are yours to choose).
3. Type the wording. Use the buttons above the box for bold (B), italic (I),
   headings, Bullets, Numbering, Indent and Outdent, Table and Field. You do not need to know any special codes. The Preview
   shows the structure; Word decides the final page layout.
4. Numbered clauses: use Numbering, then Indent to make 1.1, 1.1.1. The
   numbers you see in the Preview are the ones that appear in the document.
   Clause numbers continue from one component to the next, so numbering is
   correct however you order them. Words such as "see clause 2.1" are plain
   text and do not change if clauses move.
5. Fields work as in templates: {{Name}}, {{Fee | money-words}} and so on.
   The Field button adds one for you. If you are starting out, the picker's
   "Add starter fields…" button copies a short list (Works, Publisher type,
   Territory, Term in years, Effective Date) into your own fields; you can
   edit or archive any of them, and one you archived is never added back.
6. Titles and other special paragraphs: click in the paragraph and choose a
   style from the Style button (Normal, Title, Subtitle, Body Text or Block
   Text). Each paragraph has its own style, so one component can hold a title
   and ordinary wording. The Preview shows it. Title and Subtitle are centered
   in the finished document; centering comes from the style and nothing
   else, so there is no Center button. The button is off when the cursor is in
   a heading, a list or a table, which have their own formatting. If the page
   layout file has a style with that name, it is used as it is; if not, the
   app adds a simple one to your new document. A style change counts as an
   edit, so saving it creates a new version. Styles are kept with the
   component, not in its wording, so wording exported as plain text does not
   carry them.
7. Click Save version. Nothing you save is ever overwritten: each save is a
   new version, and Version history shows them all. Contracts that used an
   earlier version keep that wording.

Importing wording from Word

Click Import Word. ContractBuilder reads the paragraphs,
headings, bold and italic text, lists and simple tables, in order. It lists
anything it could not bring across (pictures, comments, merged table cells,
footnotes and so on) so you can check the result before saving. Page layout,
headers and footers are not imported: the Word shell supplies those. Your
original file is never changed. Paragraphs in the Word styles Title,
Subtitle, Body Text or Block Text keep that style. Other styles are
imported as Normal, and the list of notes says which. Text that was centered
or right-aligned by hand is not kept as centered; choose the Title or
Subtitle style for it in the editor.

Building a contract from components

1. In the Components window choose Build assembly.
2. Type a name for the assembly, then choose a page layout file (a "Word
   shell"; see the next section) with the "Choose page layout file…" button.
   Saving and creating a document both need these two things.
3. Add components with "Add selected component". Use Move up, Move down and
   Remove to set the order. Untick Include to leave out an optional
   component without removing it.
4. The preview on the right shows the whole contract in order.
5. Save assembly keeps this recipe, including the exact version of every
   component. Open saved brings it back later.
6. Fill fields and create document asks for each field once, even if several
   components use it, and can load a saved publisher profile. Check the
   values, then save. The result is a new Word file; the shell and the
   components are not changed.

When wording changes later

If you save a newer version of a component, assemblies that already use it do
not change by themselves. Open the assembly and choose Review updates to see
the old and new wording side by side, tick the ones you want, and save. That
creates a new revision; the earlier one is kept.

Where components are kept

Components and assemblies are stored on this computer, in the same user data
file as the publisher profiles. Nothing is uploaded. There is not yet a backup
button, so if you replace this computer, copy that file (publisher_profiles.sqlite3
in your user data folder) to the new one.

WORD SHELLS FOR ASSEMBLED CONTRACTS

A Word shell is a .docx file that supplies the page layout and formatting for
an assembled contract. Its original body wording is not included in the new
contract. The shell is copied; the original file is never changed.

Create the file in Word. Set the page size, orientation and margins. Add any
headers and footers you need. You do not have to create special styles: if
the file has no Heading 1 to 3, List Paragraph, List Bullet, List Number or
Table Grid style, or no numbering for clauses (1., 1.1, 1.1.1) and bullets,
the new document gets them added, and a short line tells you so. Your own
file is not changed. If the file already has a style with one of those names,
it is used as it is, so you can make them look the way you like.

If the file has no page settings, or cannot be read as a Word document,
ContractBuilder explains what to do. When something is worth reading first,
you choose Use this file or Choose another. For the technical details, see
SHELL-CONTRACT.md in the project repository.

UPDATES

Contract Builder checks for a newer published GitHub release when it
starts. You can also choose Help > Check for updates.

On Windows, when an update is available, choose Yes to download and install
it. A progress bar shows the download. The application then closes, replaces
itself with the new version, and opens again. Save your work first. The
download is checked against the size and fingerprint (SHA-256) GitHub
publishes for it, and is discarded if they do not match.

If the application's folder cannot be written to (for example, it is under
C:\Program Files), the new version is saved to your Downloads folder instead,
and the application says where. Close the application and use that file.

If the release has no Windows download attached, or you are on macOS, the
application offers to open the release page instead.

The first time, versions older than 0.3.0 cannot install updates themselves:
download 0.3.0 once by hand, and later versions install automatically.

OPTIONAL TOKEN FOR UPDATE CHECKS

You do not need a token for normal update checks. If you often see "GitHub is
limiting update checks from your network for now", you can add an optional
token in Help > Update settings to raise GitHub's API limit for your checks.

1. On GitHub, open Settings > Developer settings > Personal access tokens >
   Fine-grained tokens, and generate a new token.
2. Under Repository access, choose Only select repositories and pick this
   repository.
3. Under Permissions, give Contents read-only access, and nothing else.
4. In this application, choose Help > Update settings, paste the token, and
   choose Save and check now.

The token is saved for your Windows user only, beside your publisher profiles.
Never put a token in a template, script, or shared file. To stop using it,
choose Remove token in Help > Update settings.

PRIVACY

Templates, publisher profiles, and completed documents are processed locally
on your computer. Publisher details are stored in a SQLite database in your
user data directory. The application contacts GitHub only to check the latest
published release and, if you choose to install it, to download it. It does not upload your Word documents or publisher data.
