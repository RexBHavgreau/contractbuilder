BUILDING WORD TEMPLATE FILLER
=============================

The normal application is simple_app.py. app.py is a small compatibility
launcher for the same focused interface. The earlier contract-oriented GUI
has been retained separately in advanced_app.py and is not packaged.

REQUIREMENTS
============

Python 3.9 or later, plus:

    python -m pip install pyinstaller lxml

The application can be run from source:

    python simple_app.py

LOCAL WINDOWS BUILD
===================

Double-click build-windows.bat. It builds a single executable in dist.

LOCAL macOS BUILD
=================

Double-click build-mac.command. It builds a .app bundle in dist.

Build on the platform for which the application is intended. The local
scripts install PyInstaller and the DOCX XML dependency if needed.

AUTOMATIC GITHUB BUILDS
=======================

The GitHub Actions workflow at .github/workflows/build.yml runs tests and
builds Windows x64, macOS Intel, and macOS Apple Silicon versions whenever
changes are pushed to main. The generated builds are available as workflow
artifacts for 14 days.

To publish a permanent release:

1. Set APP_VERSION in version.py to the new version.
2. Commit and push the change to main.
3. Create and push a matching tag, for example v0.1.0.

The tag must exactly match APP_VERSION. GitHub Actions tests the code, builds
each platform, and attaches the finished applications to a GitHub Release.

The packaged application checks for a newer published release at startup and
from Help > Check for updates. It opens the release page for download; it does
not replace its own executable.

PRIVATE REPOSITORY
==================

The update checker cannot contain a GitHub token safely. For a private
repository, set CONTRACTBUILDER_GITHUB_TOKEN in the user's environment to a
fine-grained token with read-only Contents access to this repository. Do not
commit or distribute that token. Public repositories need no token.
