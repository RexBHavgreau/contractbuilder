# T-060 Fill in missing Word styles instead of depending on the shell having them

- **Status:** open (umbrella; work its subtasks)
- **Size:** umbrella of T-060-A and T-060-B
- **Agent:** careful
- **Needs:** —
- **Touches:** `shell_styles.py` (new); `docx_compose.py`; `shell_check.py`; `shell_selection.py`; `assembly_builder.py`; `SHELL-CONTRACT.md`; `USER-GUIDE.txt`

Beaux (2026-11-21) picked an ordinary Word file as the page layout file and
got four warnings in a dialog: no List Paragraph, List Bullet or List Number
style, and no three-level decimal outline. The file is fine for a contract; the
app is asking too much of it. Today a missing style means the wording falls
back to Normal (a bullet list loses its indent, a heading loses its look) and
the user is warned in terms they cannot act on ("shell", "decimal outline",
"explicit decimal fallback").

**Direction:** the app should add what is missing, in the **new document**,
and never ask the user to fix their Word file. Pandoc does this by taking a
reference document and supplying defaults for any style it lacks. We cannot
use Pandoc or python-docx at run time (CLAUDE.md decisions: size and
dependencies), but the converter already writes WordprocessingML with lxml, so
the missing definitions can be written the same way.

#### T-060-A Supply missing styles and numbering when composing

- **Status:** open
- **Size:** M
- **Agent:** careful
- **Needs:** —
- **Touches:** `shell_styles.py` (new), `docx_compose.py`, `shell_check.py`
- **Size gate:** yes (a small pure-lxml module; say what it adds and confirm)

- [ ] `shell_styles.py`: for each style the converter uses (Heading 1 to 3,
      List Paragraph, List Bullet, List Number, Table Grid), a definition that
      is added to the **output** document's `styles.xml` only when the file
      lacks it (matching by style id **and** by display name, so a style named
      "Heading 1" with an odd id is used, not duplicated). Paragraph styles are
      `basedOn` Normal, or Body Text if the file has no usable Normal; headings
      take the Normal font with bold and a modest size step, lists get a left
      indent, Table Grid gets thin borders. Nothing the file already defines
      is changed
- [ ] Word lists some built-in styles (List Number, List Bullet) in its style gallery even when the file does not contain them yet ("latent" styles, written into the file only once used). Beaux saw exactly this on 2026-11-21: Word offered List Number, the checker said it was missing. Treat latent styles as missing and add them; a test builds a file with the style latent only
- [ ] When the file has no three-level decimal outline or bullet definition, add
      one to the output's numbering part (the merge code in `docx_compose.py`
      already remaps numbers; reuse it) so clause numbers read 1., 1.1, 1.1.1
- [ ] The source file is never modified (the existing test on that stays), a
      file with no `styles.xml` or no `Normal` still works, and a file that
      already has everything produces a byte-identical `styles.xml`
- [ ] Tests for: each style missing in turn, all missing, display-name match with
      a different id, no Normal, the output opened with python-docx in the
      tests to confirm Word-readable styles, and the headings and list items
      actually pointing at the added styles
- [ ] `shell_check` stops reporting these as warnings once they are supplied
      (they become plain notes, see T-060-B)
- [ ] Hand check in real Word: open an output made from a layout file with no
      list styles; bullets, numbered clauses and headings look right (human)
