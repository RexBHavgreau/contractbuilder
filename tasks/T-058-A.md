# T-058-A Show field help text in the fill-in form

- **Status:** open
- **Size:** M
- **Agent:** any
- **Needs:** T-043-C
- **Touches:** `component_editor/field_picker.py`, `ui_widgets.py`, `assembly_document_window.py`, `simple_app.py`
- **Size gate:** yes (UI changes only; no new dependency or data file)

T-043-A stores a short description for each field, and T-043-C provides the
field creator. The description should help the person filling in a document
without changing the short field name used in the wording.

- [ ] The fill-in windows for both an ordinary Word template and an assembled
      contract show the stored description beside or under the field name in
      plain words. A field without a description looks exactly as it does now.
- [ ] The field creator and editor have a clearly labelled **Help text** box
      with a short example; saving preserves the description already stored
      by T-043-A.
- [ ] Matching a placeholder to its saved field definition ignores case and
      spacing, consistently with the existing field-name matching rules.
- [ ] Tests cover both fill-in workflows, a field with help text, a field
      without help text, editing the description, and matching despite case
      and spacing differences.
- [ ] No field description is inserted into the completed document; it is
      guidance for the form only.

**Done when:** a person filling in either kind of document sees the field's
help text, while the document wording and fields without help text behave as
before.

Note 2026-11-21 (from T-043-D): the form display of help text and the case/spacing matching are done (`FieldInput.help_text`, `publisher_profiles.field_help_for`, `PublisherProfileStore.field_help_map`). What remains here is the **Help text** box and example in the field creator and editor, and tests for editing the description.
