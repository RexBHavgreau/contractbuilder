# T-062 Ask once for a number and show it in digits and in words

- **Status:** open
- **Size:** L (split into T-062-A to T-062-C)
- **Agent:** careful
- **Needs:** T-043-C (field picker, merged in v0.4.2)
- **Touches:** `core.py`; `field_picker.py`; `component_editor/fields.py`; `library.py`

Beaux (2026-11-21): the fill-in window asks separately for, for example, the
number of copies "(Spelled Out)" and the number of copies "(Digit)", and the
same for the number of years. The user should type the number **once**, in
digits, and the contract should use it in both forms.

The engine already lets one field appear in several formats
(`{{Copies | number}}` and `{{Copies | number-words}}` ask once). Two things stop
the components using that: the existing wording was written with two
separate fields, and `number-words` writes **"ten (10)"**, digits included,
where wording such as "one" or "seven" alone is wanted.

#### T-062-A Words-only format

- **Status:** open
- **Size:** S
- **Agent:** careful
- **Needs:** —
- **Touches:** `core.py`
- **Size gate:** yes (no new content; confirm)

- [ ] A format `number-spelled` (aliases `spelled`, `spelled-out`) writes the number
      in words only (`ten`, `seven`); variants for capital first letter and
      all capitals; it uses the same checks as `number` (whole numbers, a
      plain message for anything else) and shows the same kind of box
- [ ] Added to `FORMAT_ALIASES`, the in-app format list and the guide's format
      table; a field used in both `number` and `number-spelled` forms is asked
      for once
- [ ] Tests, including zero, one, large numbers and a field used in three
      formats

#### T-062-B Offer the other form in the picker

- **Status:** open
- **Size:** S
- **Agent:** any
- **Needs:** T-062-A
- **Touches:** `field_picker.py`, `component_editor/fields.py`
- **Size gate:** yes

- [ ] When a number field is inserted, the picker asks **Show as: digits / words
      with digits / words only** and inserts the matching format; inserting
      the same field again offers the other forms, so "ask once, show in both
      forms" needs no typing
- [ ] Tests

#### T-062-C Combine two fields that mean the same thing

- **Status:** open
- **Size:** M
- **Agent:** careful
- **Needs:** T-062-A
- **Touches:** a new module `field_merge.py`, `library.py` (new component versions only, no schema change)
- **Size gate:** yes

- [ ] A **Combine fields…** tool in the Components window: pick two or more field
      names that are really one value (for example the "(Digit)" and "(Spelled
      Out)" pair), pick which is kept and which format each occurrence gets;
      it lists every component using them, shows the old and new wording, and
      after the user agrees saves a **new version** of each (old versions are
      never changed); assemblies already pinned to old versions are not
      altered until the user reviews updates
- [ ] A field with a stored definition (T-043-A) keeps its description; the
      combined name is added to the saved fields and the old names archived
- [ ] The fill-in window then asks once; tests with a temporary database,
      including a field that appears in a conditional and in a table

**Done when:** the number of years, and the number of copies, are typed once
and appear in whichever forms the wording asks for.
