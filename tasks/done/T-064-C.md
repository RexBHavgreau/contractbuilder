- [x] After choosing a Word file, **Import Word** asks **Whole document, part of it, or
      split into components and an assembly**; the first goes on exactly as today
- [x] **Part of it** shows the document's blocks in order with a tick box and a
      one-line preview of each (shift-click for a range, a "select all" and a "clear"),
      warnings shown beside the blocks they belong to; the ticked blocks go to the
      existing review window as one component, with their paragraph styles
- [x] A selection that cuts a list or a table in two is allowed but says so; nothing
      is saved until the review window's own Save
- [x] Tests under a virtual display; guide text; hand check on Windows (moved to UT-003, a person's check that does not block this task)

Note 2026-11-22: new modules `import_choice_dialog.py` (asks Whole document or Part of it; the split choice appears only when `split_available` is set, which T-064-D will do), `import_selection.py` (pure rules: block labels and previews, `selection_import`, `selection_notes`) and `import_selection_dialog.py` (the tick list). `ImportReviewDialog` takes an optional ready import result and default name, so the review window is the same for a whole file and for a part; the whole-document path is exactly as before. A list or a table is one block and is taken whole, so "a selection that cuts a list in two" cannot happen inside a block; the notes instead say when blocks between the first and last choice are skipped, and when a numbered list is taken without the list just before it (its numbers start again at 1). The note about styles the editor does not offer is recomputed for the chosen blocks, headers and other document-level notes still show, and the paragraph styles (Title and so on) travel with the chosen paragraphs. Tests: `tests/test_import_selection.py`.
