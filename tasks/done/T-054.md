# T-054 One file per task and a generated board

- **Status:** done on the branch (Claude, 2026-11-20); [PR #49](https://github.com/RexBHavgreau/contractbuilder/pull/49), CI run pending. Beaux has not yet decided whether the Actions bot may commit the board (the workflow keeps that off until the repository variable `BOARD_BOT_COMMIT` is set)
- **Size:** M
- **Agent:** careful
- **Needs:** T-053 (done); Beaux for the bot decision, which can follow
- **Touches:** `TASKS.md`, new `tasks/`, `scripts/`, one workflow
- **Size gate:** no executable change (say so)

`TASKS.md` is about 1,300 lines; the board table in it is edited by every
task. Agents often work on different subtasks of one task at once (T-043-A
and T-043-B), so the unit of conflict is the subtask.

- [x] `tasks/T-NNN.md` for each umbrella or standalone task, and
      `tasks/T-NNN-X.md` for each subtask, each with a header (status, size,
      agent, needs, **touches**, size gate) and its checklist. Done tasks go
      to `tasks/done/` for a month, as now. A script converts the current
      `TASKS.md` and a check proves the text is unchanged
- [x] `scripts/board.py` reads the headers and writes the board; nobody edits
      a board by hand. `TASKS.md` shrinks to "How to use this file", the
      Size gate and CI rules, and a link to the board
- [x] The board is rebuilt by a workflow on `main` after each merge and
      committed by the Actions bot (pull requests never touch it). If Beaux
      does not want bot commits, the workflow publishes it as the job summary
      and as an artifact, and `python scripts/board.py` prints it on demand
- [x] Links between tasks keep working (they use the task number, not a
      heading anchor)
- [x] Tests for the header parser and board generator, with invented tasks

**Result (2026-11-20):** `TASKS.md` (2,840 lines) became the rules only; the
tasks are 110 files (40 open in `tasks/`, 70 finished in `tasks/done/`), plus
`tasks/notes/` for the group introductions, the technical notes of T-019 and
the suggested order, and `tasks/README.md`. A one-off script split the old file
and proved it lost nothing: every non-blank line of the old task sections is
in exactly one new file (2,186 of 2,188; the two missing lines are the section
headings "Open tasks" and "Done tasks", which no longer exist). The task
files keep the existing bullet format, so no header was rewritten and the
board script reads the bullets as they are (`scripts/task_files.py`,
`scripts/board.py`, `tests/test_board.py`; the tests also check the real
files). Links between tasks use the task number, and no anchor links existed
in task bodies. The workflow `board.yml` builds the board after each merge
that touches `tasks/`, publishes it as the run summary and an artifact, and
commits `BOARD.md` only if the variable `BOARD_BOT_COMMIT` is `true`.
Not checked: the workflow itself (it only runs on `main`); the CI run of the
pull request. The `Touches` field is still empty on most tasks (T-055).

**Done when:** claiming or finishing a task edits only that task's file.
