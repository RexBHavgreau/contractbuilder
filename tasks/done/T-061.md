# T-061 Choose a paragraph style in the component editor (Title, Subtitle, Body Text...)

- **Size gate:** yes

Beaux (2026-11-21), after the first contract was built from components: the
title came out as an ordinary paragraph because the editor has no way to say
"this is the title". Headings (`#`) already map to Heading 1 to 3; Title,
Subtitle, Body Text and similar do not. He wants the style chosen **in the
component editor**, applied **when the document is created**, so the output
looks right without anyone repairing it in Word afterwards.

Today every non-heading, non-list paragraph is written in Normal, and the
three-level headings are the only style the wording can request
(`md_to_word.py`). The layout file may define more (a file Beaux uses has
Title, Subtitle, Body Text, Body List, Block Text and Table Signature).

**Decided 2026-11-21 (Beaux): the style is chosen per paragraph, and the
wording stays plain Markdown with no new syntax.** A component is often several
paragraphs that belong together but need different styles, so a
whole-component style does not work, and a marker inside the text would make
exported components harder to reuse elsewhere. So the choice is kept **beside**
the Markdown, in the component's stored data (a list of paragraph position and
style name), and exported Markdown is just the wording. Consequences the
design must handle: editing the text shifts paragraph positions, so the editor
keeps them in step (insert, delete, split, merge, move, paste, import);
a version stores the list with its wording, so the version is still immutable;
the plain Markdown export loses the styles (say so in the export note, and offer
to export the styles in a separate small file if wanted later).
