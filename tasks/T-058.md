# T-058 Field help text and calculated starting values in the fill-in window

- **Status:** open
- **Size:** L (split into T-058-A and T-058-B when claimed)
- **Agent:** careful
- **Needs:** T-043-C (field creator), T-043-A (done)
- **Touches:** `library.py` (one schema migration; only one open task adds a migration at a time, so wait for T-046-A to merge), `field_defaults.py` (new), `ui_widgets.py`, `assembly_document_window.py`, `simple_app.py`
- **Size gate:** yes (a small pure-Python module; confirm)

Beaux (2026-11-21): a field keeps one short name in the wording (`{{Signing
Deadline}}`) while the fill-in window can say more, and some fields can fill
themselves in from another field and still be changed by hand.

Example: the wording uses `{{Signing Deadline}}`. The form shows the label
**Signing Deadline (30 days after effective date)** and starts with the date
worked out from **Effective Date** plus 30 days. The user can type over it.

T-043-A already stores a short description for each field. Nothing shows it
in the form yet, and there is no way to calculate a value.

**T-058-A Help text in the form**

- [ ] The fill-in windows (assembly and Word file) show the field's stored
      description beside or under its name, in plain words; the name in the
      wording does not change, and a field with no stored definition looks as
      it does today
- [ ] The field creator and editor (T-043-C) have a clearly labelled
      **Help text** box with an example
- [ ] Tests; a Word file whose field names match stored fields gets the help
      text too (matching ignores case and spacing, as elsewhere)

**T-058-B Calculated starting values**

- [ ] A field definition can carry one **starting value rule**, chosen from
      plain choices, never typed as a formula: **a number of days, weeks,
      months or years after or before** another date field; **same as**
      another field; **today**
- [ ] A migration adds the rule to the field definitions (backup and
      transaction as before) and an older app must not downgrade the file
- [ ] `field_defaults.py`: pure functions that compute the value from the
      other values, with tests for month ends (31 January + 1 month), leap
      years, a blank or unreadable source date (no value, and a plain note)
      and a rule that points at itself or loops
- [ ] The form fills the value in when the source field is entered or
      changes, **until the user edits that field by hand**; after that it
      leaves it alone, and a small **Recalculate** control brings the rule
      back. The result is shown in the same format as the source date
- [ ] The rule never writes anything the user cannot see and change before
      the document is created
- [ ] Hand check on Windows

**Done when:** the Signing Deadline example above works in an assembled
contract: type an effective date, see the deadline appear, change it, and the
created document uses the changed value.
